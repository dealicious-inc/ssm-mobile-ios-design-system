# Plan Template Contract

## 목적

이 문서는 `ssm-mobile-ios-design-system`에서 AI가 작성하는 계획 문서 `.ai-workspace/plans/{N}-{slug}.md`의 출력 템플릿 정본이다.

AI는 계획을 작성하거나 갱신하기 직전에 이 문서를 읽고, heading 이름과 순서를 기본값으로 유지한다.

## 적용 규칙

- 계획 문서는 한국어로 작성한다.
- 계획 산출물은 `.ai-workspace/plans/`에 두며 git에 추가하지 않는다.
- 계획이 둘 이상으로 나뉘면 파일을 쪼개고, 파일명 앞에 수행 순서 번호를 붙인다.
- 쪼갠 계획은 각각 자체 완결로 작성한다. 한쪽만 읽어도 결정과 제약을 알 수 있어야 한다.
- 값이 없으면 섹션을 삭제하지 말고 `없음`, `보류`, `확인 필요`처럼 짧게 채운다.
- `사용자 확인 필요`는 항상 최상단에 둔다.
- 단계를 완료하면 상태 표를 같은 PR에서 갱신한다.
- 결정이 바뀌면 관련된 모든 계획 문서를 함께 갱신한다.
- 저장소 정본 문서(`AGENTS.md`, `docs/ai/**`)에 특정 계획의 라우팅이나 규칙을 넣지 않는다. 계획은 산출물이고, 정본은 계획을 다루는 방법만 정의한다.

## 확인 필요 게이트

계획 설계 중 사용자가 결정해야 하는 사항이 나오면 임의로 가정하고 진행하지 않는다.

- 결정 사항은 `사용자 확인 필요` 섹션에 질문 형태로 남긴다.
- 질문마다 `이유`와 `현재 기본 가정`을 함께 적는다. 사용자가 답하지 않아도 무엇이 어떻게 진행될지 알 수 있어야 한다.
- 메타데이터의 `확인 필요`를 `있음`으로 둔다.
- `확인 필요: 있음`인 계획은 사용자 확인 또는 리스크 수용 기록 없이 구현 단계로 넘어가지 않는다.
- 해당 결정에 의존하지 않는 단계는 먼저 진행할 수 있다. 이때 어떤 단계가 확인 대기로 막혀 있는지 상태 표에 남긴다.
- 확인이 끝나면 질문을 지우지 말고 `확정된 결정` 표로 옮기고 확정일을 적는다.
- 확인할 것이 없으면 `없음`으로 적는다.

## 고정 템플릿

````md
# 계획 {N}. {제목}

## 사용자 확인 필요

1. 없음
   - 확인할 내용이 있으면 질문을 한 문장으로 쓰고, 하위 줄에 이유와 현재 기본 가정을 적는다.
   - 이유:
   - 현재 기본 가정:
   - 이 결정에 막히는 단계:

## 목적

- 이 계획으로 달성할 목표를 적는다.
- 관련 계획이 있으면 파일명과 수행 순서를 적는다.

## 상태

| 항목 | 값 |
| --- | --- |
| 상태 | 착수 전 / 진행 중 / 완료 / 보류 |
| 확인 필요 | 없음 / 있음 |
| 최종 갱신 | YYYY-MM-DD |
| 예상 규모 |  |

| # | 단계 | 브랜치 | 상태 |
| --- | --- | --- | --- |
| N-0 |  | - | 미착수 |

## 확정된 결정

| 항목 | 결정 | 확정일 |
| --- | --- | --- |
|  |  | YYYY-MM-DD |

## 배경

- 측정 시점을 적는다.
- 근거가 되는 파일 경로와 수치를 함께 남긴다. 나중에 코드가 바뀌었을 때 문서가 낡았는지 판별할 수 있어야 한다.

## 목표 구조

- 도달하려는 구조를 적는다. 필요하면 계획용 코드 블럭이나 다이어그램을 쓴다.

## 단계 상세

### N-0 {단계명}

- 산출물:
- 착수 조건:
- 완료 조건:

## 되돌리기

- 롤백 방법과 안전망을 적는다.

## 작업 중 규칙

- 이 계획이 완료되기 전까지 해당 영역에서 지킬 것을 적는다.

## 금지

- 이 계획 고유의 금지사항만 적는다.
- `AGENTS.md`의 공통 금지 항목은 반복 노출하지 않는다.
````

## 금지 패턴

- `사용자 확인 필요`를 상단이 아닌 곳에 두는 것
- 결정 사항을 질문으로 남기지 않고 임의 가정으로 진행하는 것
- 확인이 끝난 질문을 `확정된 결정`으로 옮기지 않고 삭제하는 것
- 계획 문서를 `docs/ai/**`에 만들어 커밋 대상으로 두는 것
- 특정 계획의 이름이나 경로를 `AGENTS.md`에 하드코딩하는 것
