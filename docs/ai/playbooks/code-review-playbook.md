# Code Review Playbook

## 목적

이 문서는 `ssm-mobile-ios-design-system`에서 AI가 코드 리뷰를 수행할 때 따르는 공용 기준이다.
PR 리뷰, 로컬 diff 리뷰, 특정 파일 리뷰에 사용할 수 있다.

## 비교 기준

- PR 리뷰 기본 비교 기준은 `origin/dev`다.
- 로컬 작업 리뷰는 사용자가 지정한 diff 기준을 따른다.
- 리뷰 중 코드는 수정하지 않는다.

## 리뷰 순서

1. 변경 파일 목록과 diff 범위를 확인한다.
2. 아키텍처, 컴포넌트 구조를 확인한다.
3. 컴파일/런타임/보안/메모리 위험을 확인한다.
4. Findings를 심각도 순으로 작성한다.

## 반복 리뷰 원칙

- 이슈는 `이슈 1`, `이슈 2` 형식으로 번호를 고정한다.
- 재리뷰에서도 기존 이슈 번호를 유지한다.
- P0/P1/P2 finding이 남아 있으면 `Pass`로 판정하지 않는다.

## 공통 체크리스트

- `AGENTS.md`의 기본 수정 금지 항목을 위반하지 않았는가
- 설명 주석과 Swift 네이밍이 `swift-style.md`와 맞는가
- 신규 class가 상속 필요 없이 non-final로 추가되지 않았는가
- `then` / `do`, `addSubview`, constraint 설정 순서가 기존 UIKit 패턴과 맞는가
- UIKit 컴포넌트와 SwiftUI 컴포넌트가 같은 타입/enum을 공유하는가
- SampleApp에 새 컴포넌트가 반영되어 있는가
- public API가 적절하게 노출되어 있는가
- generated 파일을 직접 수정하지 않았는가

## 네이밍 리뷰 기준

- 같은 컴포넌트 안에서 이름 체계가 일관적인가
- 명백한 오타가 남아 있지 않은가
- Bool 이름은 `is`, `has`, `can`, `should` 접두사를 따르는가
- 디자인 시스템 컴포넌트는 `Deali` prefix를 사용하는가

## 메모리 릭 체크

- 클로저에서 `self`를 강하게 캡처하는 Rx 바인딩
- `DisposeBag`에 넣지 않은 구독
- `delegate`를 `strong`으로 보유하는 순환 참조

## 크래시 가능성 체크

- 강제 언래핑 `!`
- 강제 다운캐스팅 `as!`
- 배열 인덱스 범위 오류

## Finding Severity

| Severity | 의미 |
| --- | --- |
| P0 | 크래시, 데이터 손상, 배포 차단급 문제 |
| P1 | 주요 회귀 위험, 아키텍처 위반 |
| P2 | 수정해야 하는 규칙 위반 또는 유지보수 위험 |
| P3 | 선택적 개선 제안 |

## 출력 형식

````md
## 코드 리뷰 결과

- 결과: 통과 / 수정 필요 / 차단
- 리뷰 대상:
- 비교 기준:

### 발견 이슈

#### 이슈 1 [P1] 제목

- 파일:
- 근거:
- 문제:
- 영향:
- 권장 수정 방향:

As-Is:

```swift
// 현재 문제가 되는 코드
```

To-Be:

```swift
// 권장 수정 방향
```

### 검증 공백

- 수행하지 못한 검증:
- 남은 리스크:

### 요약

- 변경 요약:
- AI Document Impact:
````

## Pass 조건

- P0/P1/P2 finding이 없다.
- 검증하지 못한 항목이 있으면 잔여 리스크가 기록되어 있다.

## 금지 패턴

- 변경 요약을 findings보다 먼저 쓰는 것
- 이슈 번호 없이 finding을 나열하는 것
- 코드로 설명 가능한 이슈인데 코드 snippet 없이 텍스트 설명만 쓰는 것
- 취향성 제안을 필수 수정처럼 쓰는 것
